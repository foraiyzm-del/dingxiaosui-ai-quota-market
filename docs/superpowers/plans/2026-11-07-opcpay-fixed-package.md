# 一人付固定套餐实施记录

**目标：** 在独立本地副本实现“丁小穗尝鲜卡”权益兑换，9.90 元、文案 10／图片 15／视频 2；1 次 COUNT 权益兑换 1 张卡。

**基线：** `main` / `3094ec4393e8faff8ecdb9bfac1dc7af089ef0dc`，分支 `feat/opcpay-fixed-package`。用户提供的完整交接为本次实施规格，已明确授权本地实现、隔离模拟和浏览器演示；不推送、不部署、不动生产。

**架构：** 一人付作为独立权益兑换入口，与原 manual/epay 并存。稳定服务端买家身份、秘密恢复码和 HttpOnly 会话；意向、购买请求、核销业务号及参数均持久化。查询原核销结果，明确成功后复用库存交付事务。权益交付有明确 settlementKind，排除现金营收，不调用人工核账 approveOrder。

**范围选择：** 按用户指定的 consume/consumption 流程实现；不采用余额差反推现金订单，不接权益 Webhook，不扩展全站账号。保留丁小穗所有已有作品、额度与媒体恢复代码。真实商户配置与人工扫码付款留到本地验收之后。

## 必须检查的故障

1. consume 超时或响应丢失：持久原编号，不能生成新编号重新扣减。
2. 已核销后发卡失败或进程重启：继续原交付，不因意向过期或取消丢权益。
3. 同浏览器、不同标签和并发请求：只使用一个活动意向，只扣一次并交付一张卡。
4. 修改客户端价格、SKU、quota、userId：服务端拒绝或忽略，不改变固定快照与身份。
5. 核销回执不匹配、混用计费单位、真实套餐漂移：阻止交付并保留核对记录。
6. API Key、恢复码、卡密：不进入公共日志、报告或截图。
