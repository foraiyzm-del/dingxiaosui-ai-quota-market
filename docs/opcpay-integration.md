# 一人付固定尝鲜卡：安装、演示与真实验收

本地权益兑换已扩展为丁小穗尝鲜卡、周卡和月卡，三档分别绑定专用收款项目。**2026-11-07 已在开发副本完成用户确认实付 9.90 元、真实核销 1 次、发卡及丁小穗激活验收；未部署或推送。** 逐笔现金支付由用户确认，API 仅证明权益和核销。随后已将原本地实付账本、商户配置及项目凭证迁入独立商城 3399；本机已开放三档支付宝入口，周卡与月卡真实付款尚未验收；其他套餐保留，一二大模型只留入口，本轮未新增付款或核销。最新结果见 [独立商城支付接通验收](standalone-payment-connected-20261107.md)，前序实付证据见 [真实支付与交付验收](opcpay-live-acceptance-20261107.md)。

源码基线为 `3094ec4393e8faff8ecdb9bfac1dc7af089ef0dc`，分支 `feat/opcpay-fixed-package`。核对日期：2026-11-07。一人付协议来源与边界见 [协议核对记录](opcpay-provider-contract.md)。

## 固定规则

| 项目 | 服务端固定值 |
| --- | --- |
| 本地商品 | `dingxiaosui-opcpay-trial` |
| 本地 SKU | `trial` |
| 名称 | 丁小穗尝鲜卡 |
| 售价 | 990 分，即 9.90 元 |
| 卡内额度 | 文案 10 次、图片 15 次、视频 2 次 |
| 一人付计费 | `QUANTITY / COUNT / QUOTA`，`quota_amount=1` |
| 兑换 | 核销 1 次权益 → 交付 1 张完整额度卡 |

27 是卡内额度总和，不是一人付购买或核销数量。真实一人付项目须专用于这一套餐且只包含一个 SKU，因为 `access/consume` 返回项目级聚合权益，不能证明某次核销对应某笔 9.90 元现金交易。

## 直接演示（没有真实付款）

先关闭**自己刚启动的**原联合服务；不要停止其他目录或其他人的服务。

```powershell
node scripts/start-opcpay-demo.mjs
```

该脚本先独占检测 3199、8845、13999 三个端口；占用时退出，不连接已有服务。可用 `OPCPAY_DEMO_PORT`、`OPCPAY_DEMO_DING_PORT`、`OPCPAY_DEMO_MOCK_PORT` 指定其他空闲端口。

- 商城：`http://127.0.0.1:3199/`
- 固定套餐：`http://127.0.0.1:3199/opcpay`
- 后台：`http://127.0.0.1:3199/admin`
- 丁小穗：`http://127.0.0.1:8845/workbench.html`

操作：

1. 商城点击「一人付尝鲜卡」，核对 9.90 元和三项额度。
2. 创建兑换账户，下载并私密保存恢复码，再勾选已保存。邮箱不是账户凭证。
3. 确认套餐创建兑换意向。未购买时点击「查询权益并兑换 1 张卡」，页面应显示尚无权益，不发卡。
4. 打开购买入口，再打开明确标识为模拟的购买页。可选择成功、购买拒绝、消费拒绝、扣减成功但响应丢失。
5. 返回套餐页，点击「查询权益并兑换 1 张卡」。未知状态只查原记录，已开始的核销由后台每 15 秒恢复；不要重复购买。
6. 交付后复制卡密，点击「去丁小穗激活」，在真实工作台激活。余额应为 10／15／2。
7. 刷新或重启服务后查看原记录，卡密不变。同码再次激活仍为原作品空间与剩余额度。

模拟数据持久保存在 `local/opcpay-demo/`。其中包含中心、模拟一人付和丁小穗的独立数据库，以及自己的密钥和运行快照。不会读取原本机或生产数据。模拟 API Key 仅是假值；模型 HTTP 由显式 fixture 接管，未定义外部网络一律拒绝。此模式不代表支付宝已接通。

Ctrl+C 关闭本脚本创建的服务。再次运行同一命令恢复原数据。不要删除密钥后保留数据库，也不要把模拟库用作真实商户库。

## 私密商户配置与只读核对

```powershell
node scripts/setup-opcpay.mjs
```

它只创建被 Git 忽略的 `local/opcpay.json`，不会覆盖已有文件。请用本机编辑器填写，不在聊天、命令参数、截图、日志中提供 Key：

| 字段 | 要求 |
| --- | --- |
| `apiKey` | 对应专用收款项目的真实服务端 Key |
| `skuId` | 一人付后台已审核的真实 SKU，不是本地 `trial` |
| `merchantProjectName` | 真实项目名称，与 `/product` 返回值完全相同 |
| `enabled` | 资料确认完毕后设为 `true` |
| `sandbox` | 真实配置必须是 `false` |
| `termsConfirmed` | 商户确认允许核销后交付自有卡，且退款售后路径已明确后才设 `true` |
| `projectId/productId/packageId` | 保留模板固定值 |
| `verifiedPackage` | 保留 `priceCents:990, quotaUnit:"COUNT", amount:1` |
| `baseURL` | 可选；默认 SDK 官方地址。仅经商户核对后变更 |

然后运行：

```powershell
node scripts/probe-opcpay.mjs
```

探针只读 `/capabilities` 和 `/product`，报告项目、套餐及具体差异，不输出 Key，不创建购买、不核销。没有 Key 时直接退出。SDK 默认域名与公开 OpenAPI 的 servers 域名不同，真实商户必须通过该探针确认；不能把公开文档样例当成账户实际 capabilities。

本次已保留旧 `nsy` 四套餐项目，另建并核对丁小穗专用收款项目，只含 9.90 元／COUNT 1 的尝鲜卡，交付说明为“核销 1 次权益交付 1 张文案 10／图片 15／视频 2 的自有额度卡”。用户已确认平台允许该交付方式，退款由官方客服人工处理。新项目使用自己的 API Key 和 SKU，Key 仅在私密配置；旧 Key 不会自动切换项目。其他部署仍须按其商户后台及平台答复核对这些条件。

## 真实 9.90 元验收与迁移后的运行方式

当前本机已完成实付验收和迁移。商城在 `E:\codex\quota-market-standalone` 执行 `npm start`，使用 3399；丁小穗在完整仓库执行 `node scripts/start-dingxiaosui-attached.mjs`，使用 8945 并连接独立中心。它沿用原应用数据、密钥及构建快照，商城入口更新为 `http://127.0.0.1:3399/?project=dingxiaosui`；`localModelMock:true` 保持模型模拟。

以下命令仅记录迁移前的实付验收启动方式。原 3499 服务已经停止，`local/opcpay-live-test/MIGRATED.json` 会阻止旧联合脚本重新启动该中心，不应删除标记或恢复旧账本继续收款：

```powershell
$env:OPCPAY_DEMO_PORT = '3499'
$env:OPCPAY_DEMO_DING_PORT = '8945'
node scripts/start-opcpay-demo.mjs --live-payment
```

迁移前，此显式选项使用 `local/opcpay-live-test/` 的独立身份、中心和丁小穗测试库；首次启动初始化，之后重启保留原记录，并读取私密真实商户配置。模型仍被模拟，不产生真实模型费用。已有模拟身份库禁止切成真实模式。脚本名称保留 demo 是为了共用本地测试启动器，`--live-payment` 确实允许一人付请求，控制台会明确说明。

上述历史端口为 3499 商城与 8945 丁小穗。当前有效商城和固定卡地址分别是 `http://127.0.0.1:3399/`、`http://127.0.0.1:3399/opcpay`，丁小穗工作台仍是 `http://127.0.0.1:8945/workbench.html`；均为本机地址，不是公网产品地址。

付款前必须向操作者核对：**实际金额 9.90 元、真实收款项目名称、丁小穗尝鲜卡、COUNT 1 次权益**。本次专用项目已完成配置和只读核对，用户通过商城原购买入口的官方二维码亲自付款。页面优先展示上游二维码图片，宽度 320，加载失败时回退本地生成的原购买深链二维码。

用户打开固定套餐页，保存恢复码并创建意向；服务端检查实际 capabilities/product 后展示支付宝购买链接或二维码。用户用支付宝扫码、核对收款信息并亲自付款。随后查询权益并兑换，核对仅核销一次、仅交付一张卡、激活为 10／15／2，并刷新、重启验证原卡不变。购买返回和 Webhook 都不能替代该验收。本实现不接 Webhook。

迁移前实付结果：用户确认实付 9.90 元；权益 1 → 核销 1 → 余额 0，原核销 `SUCCEEDED`、`confirmed=true`、`consumed=1 COUNT`，列表仅 1 条。本地仅 1 笔权益订单、1 张库存卡、1 张已激活卡，实际丁小穗显示 10／15／2。重复激活、刷新、同买家恢复及 3499／8945 服务重启后仍为同卡同余额。验收中的脱敏占位值误读及隔离库恢复码重置经过见 [最新验收记录](opcpay-live-acceptance-20261107.md)，不据此诊断源码格式缺陷。

本轮迁移后，原 2 个买家、1 个已交付意向和 1 个等待权益到账意向保留，没有新增付款或核销。3399 页面可查看原卡，8945 显示原余额 10／15／2；这验证迁移连续性，不是新支付验收。

**付款后不要根据余额变化标记某笔本地现金订单已付。** 本地记录是权益兑换，`ENTITLEMENT:` 仅为内部权益回执，不是支付宝流水；现金到账时间为空，后台现金累计排除这些记录。

## 实现与恢复

- 服务端生成稳定 provider 用户；浏览器仅持有 HttpOnly/SameSite Cookie。恢复码只存 HMAC，恢复轮换会话，退出在服务端撤销会话；有效期 365 天。
- 创建意向时保存固定套餐、价格、额度、媒体规格和稳定购买/消费编号；同买家、同套餐的新请求复用已有未结束意向；不同套餐分别保留意向，同一请求编号不能改换套餐。
- 核销参数先落库。网络未知、PROCESSING、不匹配回执都不发卡；先查原 `/consumption`，仅明确 `404 NOT_FOUND` 才允许原编号原参数重发。
- 核销确认先持久化，库存签发和交付在本地事务中完成，唯一 `redemption_id` 保证失败/重启后只交付同一张卡。
- 未开始核销可取消；核销开始后不再取消或超时丢弃。取消购买意向不会撤销已到账的项目权益，可用同身份另建意向兑换。
- Key 轮换可查询原消费并恢复匹配成功回执；新 Key 查不到原消费时不自动重新扣减。变更商户项目/套餐/基址需人工核对原记录。
- `manual/epay` 保留，不能对权益订单人工核账或发起易支付。创建兑换意向只接受 requestId 和受支持的 packageId，套餐及额度由服务端确定；浏览器提交的 userId、价格、额度和上游 SKU 等越权字段被拒绝。

## 退款和上线边界

公开接口当前没有逐笔交易查单、退款、账单或核销撤销能力。不能把额度释放、取消意向或作废卡密称为现金退款。

用户已确认本项目退款通过官方客服人工处理，平台允许核销后交付自有额度卡；这项确认不等于退款已执行。售后应核对真实交易并人工登记退款结果、核销回执和卡密交付状态。已激活/已消费卡需单独核对剩余额度与售后方案；当前适配没有自动扣回额度或核销反向操作，不能声称已经实现自动退款。

本开发副本已完成上述真实支付与交付验收；上线仍需部署环境的商品与商户配置核对、HTTPS 与域名配置、私密配置管理及数据库/加密主密钥成套备份。本次运行是单进程 SQLite，没有验证多实例并发、公开生产部署、真实模型质量或实际退款，也没有部署、推送或修改生产。
